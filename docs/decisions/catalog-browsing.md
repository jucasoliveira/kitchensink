The old catalog worked through a JSP bean called `CatalogHelper`. You set one property at a time (start, count, locale, whatever was typed in the search box) and then asked it for a page of results. I kept the same seven operations but dropped the mutable bean: `CatalogService` takes what it needs as arguments, so two requests can never trip over each other's half-finished state. The paging surprised me. It looks lazy, because it reads the whole list and then cuts a slice out of it in memory rather than asking the database for only the rows it wants. But that is what the 2003 app did too: every query ran unbounded and the code then walked the cursor forward to the row you asked for. So it is faithful rather than a corner cut, and with twenty-eight items in the catalog it is not pretending to be anything else. Three small oddities came along with that loop and I kept all of them, each with a test saying it was on purpose: asking for zero rows gives you one, paging past the end leaves you with no links at all (not even Previous), and Previous off a short last page steps back too little, so you re-read a row you just saw. Then three things I changed deliberately. The first is ordering. Categories and products were sorted by name and still are, but items and search results were not sorted at all, which makes paging meaningless, because page two only means something if page one came out of the same order. The old app got away with it only because its one database happened to hand rows back in the order they went in. Items and search results are now sorted by id. The second is language. Locale used to be part of a database join, so anything untranslated quietly fell out of the results on its own. Now that the translations sit inside each document nothing falls out by itself, so the service filters explicitly, and there is still no falling back to English, because there never was any. The third is the one I like most: searching for "Angelfish" with a capital A found nothing in 2003. The query lower-cased the data but forgot to lower-case what you typed, so any capital letter killed the search. I lower-case the search terms now, which is exactly what a second, switched-off copy of the same class in the original code already did. That last one is a bug I fixed rather than a behaviour I kept, and the reason it is written down here is that the difference matters: everything else is the old behaviour with a test pointing at the line it came from, and this one is a departure with a reason.
