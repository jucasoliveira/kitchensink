The legacy app seeded its catalog with a servlet: hit `/Populate?forcefully=true` and it dropped six tables, recreated them and streamed `Populate-UTF8.xml` back in. The new app does the same as a document import. A script reads the original XML and writes `seed/catalog.json`, turning six tables into three collections with the per-locale detail rows embedded under `details`; I run it and commit the output, never edit the JSON, so a diff on the fixture means the transform changed and not the data. That is the relational-to-document step a real migration would do with a mapping tool, at a size where you can read all of it. Two quirks of the old loader are kept on purpose: locale keys are stored as `en_US` because that is what the DAO queried with, and gaps are not filled, so `EST-15` still has no Japanese row and the item counts are 28 / 27 / 28. Prices stay as strings because the numeric type is the catalog domain's decision, not the seed's. The loader is one class in the Mongo adapter behind a property: on, it drops the three collections and inserts the fixture at startup; off, it does not exist. Drop and reload is idempotent, which is what you want from something you run right before a demo. It writes raw documents because the catalog domain is not written yet, and it is Mongo only until the JPA adapter for the catalog exists, which is a gap I am writing down rather than hiding.

The proof is on both sides. The legacy tree is 146 MB and git-ignored, so the tests read a verbatim copy of `Populate-UTF8.xml` in the test resources, and one test checks that copy byte for byte against the original wherever the tree is present. A parity test then pins what the copy contains: five categories, sixteen products, twenty-eight items, the per-locale counts, the missing Japanese row, the underscore keys, every reference resolving. Another boots the app against a real MongoDB container with the property on, runs the loader twice, and asserts the collections hold exactly what the first test read. The acceptance criterion was "same counts per locale as the legacy seed, one command reloads", and the point I would make in the interview is that both halves are executable: the counts are compared against the legacy file itself, not a number I remembered, and the one command is `scripts/seed.sh`.
